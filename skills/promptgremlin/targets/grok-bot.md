## All models
- Grok Bot has product docs but no prompting guide; the model underneath is the product's choice (see the xai notes). The rules below are for a durable Bot, not a one-off chat. (hand-written: no official prompting guide; bots, overview)
- A Bot is a named, long-lived agent with its own conversation and memory on a persistent cloud computer (browser, filesystem, terminal) that keeps working with your laptop closed. Write for an outcome it owns over weeks, not a single answer. (overview#What makes Grok Bot different)
- Produce two pieces when the braindump mixes them. The Bot description (Bot menu or Edit Profile) holds rules that stay true: durable preferences, boundaries, responsibilities. The conversation message holds the task of the moment. (bots#Edit a Bot)
- Describe the job in operational terms: what it owns, which inputs it pulls, what it produces, and who consumes it. Name it for a specific job; a vague "helper" role gives it little to work with. (bots#Give each Bot a clear job)
- If the braindump spans different goals, tools or sources, working styles, approval boundaries, or schedules, recommend separate Bots, keeping the roster small. (bots#Give each Bot a clear job, #Organize a team of Bots)
- Write approval boundaries into the description: which external actions (messages, account changes, spending) need sign-off. Memory is not a safe place for a boundary. (bots#What a Bot remembers, #Organize a team of Bots)
- Keep changing facts out of the description. Name the source system and tell the Bot to reopen current data before any consequential decision. (bots#What a Bot remembers)
- A good first message is a real task across a few tools: what to do, where to work, what context to pull, and what finished looks like. (overview#A good first handoff)
- Sites that block automation or need a human step get handed back; say what the Bot should do then, such as stop and report. (overview#FAQ; hand-written for the instruction)
- All Bots share one computer, files, and logins, and a shared template (public or team-only link) shows the description, skills, and routines. Never put keys, internal URLs, or customer data in either. (overview#Your Bots share one computer, bots#Share a Bot)
- A task started by tagging @bot in an X post goes to your main Bot, and the post itself is public. Keep it short, self-contained, and free of private details. (overview#Tag @bot on X; hand-written for the privacy advice)
- A recurring or repeatable path is saved as a skill or routine after the Bot does it once, so describe what each run should produce rather than the calendar. A duplicate keeps profile and routines but not memory, so restate the new scope. (overview#What makes Grok Bot different, bots#Duplicate a Bot; hand-written for the phrasing)
